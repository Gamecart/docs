API tokens authenticate server-to-server requests to `/v1/seller/*`. Use one when your backend needs to read Gamecart orders or payment status.

Gamecart stores the token hash and prefix, not the raw token. You can see the raw value only when you create or rotate it.

<Warning>
  Copy the raw token immediately and store it in your secret manager. Gamecart cannot show the same token again.
</Warning>

## Before you begin

You need:

- The Enterprise plan. A store can have up to 20 tokens.
- Permission to manage integrations for the store.
- A backend service that keeps secrets out of browser code.

## Create a token in the dashboard

1. Open **Integrations > API**.
2. Click **Create token**.
3. Enter a **Name** for the system that will use the token, such as `Order sync`.
4. Under **Scopes**, keep only what the integration needs. **Orders read** comes checked.
5. Click **Create token**.

6. Copy the token from **Save this token now** and store it in your secret manager. Tokens start with `gci_`.

## Choose scopes

| Scope | Choose it when |
| --- | --- |
| `orders:read` | Your integration needs to list orders or fetch order details, including payment status. |
| `orders:buyer:read` | Your integration needs buyer name, email, or account identifier. |

For delivery automation, `orders:read` is enough. Add `orders:buyer:read` only if the external system needs the buyer's name, email, or account identifier.

## Regenerate or delete a token

Use **Regenerate token** if a token may have leaked or your secret policy requires a new value. The current secret stops working immediately, and Gamecart shows the replacement once.

Use **Delete token** when you retire an integration or no longer trust it. Deletion is permanent, and the token stops working immediately.

## Use a token from your backend

Pass the raw token as a Bearer token:

```http
GET /v1/seller/orders
Authorization: Bearer gci_...
```

Never expose the token in storefront JavaScript, public repositories, logs, screenshots, or support messages.

Gamecart applies rate limits per token and endpoint. The current default is `120` requests per minute.

## Recommended setup

- Create one token per external system.
- Name tokens after the system, not a person.
- Keep scopes minimal.
- Regenerate tokens after team member offboarding or suspected leakage.
- Delete unused tokens instead of keeping them as backups.
