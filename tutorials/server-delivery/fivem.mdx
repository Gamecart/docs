## Before you begin

The executor is a server-only FiveM resource. It requires Cfx Node 22 and has no client scripts or NUI.

Download the current stable resource: [gamecart-fivem.zip](https://cdn.gamecart.gg/executors/fivem/latest/gamecart-fivem.zip).

## Install and configure the executor

1. Place the resource at `resources/[gamecart]/gamecart`.
2. Keep the resource folder named `gamecart` when using the documented ACE principal.
3. Open `config.js` and set your server token.
4. Add the ACE rules and `ensure gamecart` to `server.cfg`, then restart the resource.

```js
module.exports = Object.freeze({
  serverToken: "paste-token-here",
  apiUrl: "https://api.gamecart.gg",
  pollIntervalSeconds: 15,
  debug: false,
})
```

Copy the server token from **Integrations > Servers**. Keep it secret.

Set `pollIntervalSeconds` to a value from `5` through `600`. Unless you use a loopback development endpoint, `apiUrl` must use HTTPS. With `debug=true`, the executor writes sanitized state and status logs. It does not log tokens, commands, player nicknames, HTTP bodies, buyer data, or order data.

## Grant command permissions

Fulfillment uses `ExecuteCommand` under the `resource.gamecart` principal. Grant administrators access to the local commands and start the resource:

```cfg
add_ace group.admin command.gamecart allow
ensure gamecart
```

Prefer explicit command grants whenever the target resource exposes command-specific ACE objects.

<Warning>
  The broad grant below permits `resource.gamecart` to execute every registered server command. Use it only when you understand that risk.

  ```cfg
  add_ace resource.gamecart command allow
  ```
</Warning>

## Operate the executor

Run `gamecart status` to check the executor version and whether it is connected. After you edit `config.js`, run `gamecart reload` to apply it. Reloading never runs a command a second time.

Use one installation for each Gamecart server token.

If the executor can't reach Gamecart, it keeps retrying on its own and waits up to a minute between attempts. When Gamecart is reachable again, it reconnects without a reload. The console logs one line when the connection drops and another when it comes back.

If it keeps retrying with a `401` or `403` error, Gamecart is rejecting the server token. Check `serverToken` and `apiUrl` in `config.js`, then run `gamecart reload`.

<Warning>
  If a command ran on your server but Gamecart never received the confirmation, resending it can deliver the purchase twice. Stop the original executor and check the outcome in the Gamecart dashboard before you resend.
</Warning>
